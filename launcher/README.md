# NEXUS Launcher

Лаунчер Minecraft для **Windows 10/11 x64**: Java 21 + JavaFX, оформление в стиле NEXUS Client.

## Готовые файлы

Скачать: https://github.com/qwercheka-byte/nexusCLIENT/releases/latest

| Файл | Для чего |
|---|---|
| `Nexus Launcher.exe` | **Рекомендуется.** Установщик для Windows 10/11 x64: ярлыки на рабочем столе и в «Пуске», удаление через «Приложения» |
| `Nexus Launcher.zip` | То же без установки: распаковать папку `Nexus Launcher` целиком, запустить `Nexus Launcher.exe` |

Java ставить не нужно. **Ни в установщике, ни в архиве нет jar-файлов:**

```
Nexus Launcher\
├── Nexus Launcher.exe   нативный стартер (≈50 КБ, packaging/windows/launcher/NexusLauncher.c)
├── app\                 классы лаунчера и Gson + ресурсы, обычными файлами
│   └── bundled\nexus-client-<версия>+mc1.21.11.zip   встроенный NEXUS Client
├── runtime\             Java 21 + JavaFX, собранные jlink (модули в образе lib\modules)
└── LICENSE
```

`Nexus Launcher.exe` запускает `runtime\bin\javaw.exe -cp app dev.nexus.launcher.Main` без консольного окна.
Если файлов не хватает или Java падает сразу после старта, exe показывает понятное сообщение (на русском или английском, по языку Windows).
Если обновление прервалось между переименованиями папок, exe сам возвращает предыдущую версию из `app.old`.
Пакеты автообновления (zip лаунчера и NEXUS Client) лежат в папке [`updates/`](updates) репозитория, а не на странице релиза.
Установщик ставит лаунчер только для текущего пользователя в `%LOCALAPPDATA%\Programs\NEXUS Launcher`, права администратора не нужны,
и автообновление может менять файлы без UAC. Сборки, миры и аккаунты лежат отдельно (`%APPDATA%\.nexus-launcher`): переустановка их не трогает,
а при удалении программа спрашивает, удалять ли их (по умолчанию — нет). Если лаунчер или игра запущены, установщик просит их закрыть.
Java для **самой игры** лаунчер скачивает сам (официальные сборки Mojang: Java 8 / 17 / 21 / 25 в зависимости от версии).

## Возможности

- **Любые версии Minecraft** из официального манифеста Mojang: релизы, снапшоты, old alpha/beta.
  Проверено: 1.8.9, 1.20.1, 1.21.1, 1.21.4, 1.21.11, 26.3 (речь о запуске самой игры, не о NEXUS Client).
- **Загрузчики:** Fabric, Quilt, Forge, NeoForge (все проверены запуском). Forge и NeoForge ставятся их официальными установщиками.
- **Сборки (инстансы):** отдельная папка игры у каждой сборки; цвет, поиск, дублирование, удаление, смена версии, переустановка.
  Свои для сборки: память, Java, аргументы JVM, разрешение, полноэкранный режим, сервер для автоподключения.
- **Моды:** вкл/выкл, удаление, добавление файлов (в том числе перетаскиванием), каталог Modrinth с поиском и сортировкой.
  Установка из Modrinth идёт вместе с обязательными зависимостями; есть проверка и установка обновлений.
  NEXUS Client встроен в лаунчер и ставится одной галочкой в Fabric-сборки **1.21.11** (другие версии NEXUS Client не поддерживает).
  В папку `mods` сборки мод записывается как `nexus-client-<версия>+mc1.21.11.jar` — Fabric Loader загружает только файлы `*.jar`; это единственное место, где появляется jar, и появляется он только на компьютере игрока.
- **Оптимизация** (с 1.0.3): кнопка «Оптимизация» на вкладке «Моды» и галочка при создании сборки (Fabric/Quilt) ставят с Modrinth 6 модов — Sodium (отрисовка), Lithium (игровая логика), FerriteCore (память), ImmediatelyFast (HUD/текст/предметы), Entity Culling (не рисует скрытое за стенами), BadOptimizations (мелкие затраты каждого кадра) — последние версии под версию игры сборки, с обязательными зависимостями. Уже установленные и не вышедшие под эту версию пропускаются, об этом пишется уведомление. Это сторонние моды, лаунчер только выбирает набор и версии.
  Аргументы JVM по умолчанию — G1GC с короткими паузами (как в официальном лаунчере), память по умолчанию подбирается по объёму ОЗУ.
- **Аккаунты:** вход через Microsoft (device code), офлайн-профили (одиночная игра и серверы с `online-mode=false`).
  Скины-головы показываются в списке аккаунтов.
- **Запуск:** проверка и докачка файлов (SHA-1, параллельные загрузки), прогресс, отмена, остановка игры.
  Консоль с фильтром, копированием и логом прошлого запуска; при сбое — диалог с переходом в консоль.
- **После запуска игры** лаунчер можно оставить, скрыть до выхода из игры или закрыть.
- **Интерфейс:** русский / английский, 5 акцентных цветов.
- **Своя рамка окна** (с 1.0.4): вместо белой системной полосы заголовка — прозрачная полоса в стиле лаунчера с кнопками «Свернуть / Развернуть / Закрыть» (закрытие — красным). Окно двигается за верхнюю полосу, разворачивается двойным щелчком или перетаскиванием к верхнему краю экрана (развёрнутое окно занимает рабочую область, не закрывая панель задач), возвращается к прежнему размеру перетаскиванием вниз, меняет размер за края и углы. Отключается в Настройки → «Интерфейс» → «Своя рамка окна» (после перезапуска) — тогда снова обычная рамка Windows.
- **Анимированный фон из фото** (с 1.0.3): те же 13 фото, что и в главном меню NEXUS Client, — медленное приближение и сдвиг кадра, плавная смена (1,6 с), лёгкий параллакс за мышью; панели полупрозрачные, диалоги непрозрачные.
  Настройки → «Фон»: вкл/выкл, случайный порядок, затемнение 0–90 %, «Папка с фото», «Обновить фото».
  Свои PNG/JPG кладутся в `%APPDATA%\.nexus-launcher\backgrounds` — если там есть хотя бы один файл, показываются только свои (файлы больше 40 МБ пропускаются, не больше 64 фото).
  В памяти одновременно не больше двух картинок; пока окно свёрнуто или скрыто на время игры, анимация остановлена.
  Встроенные фото при сборке копируются из `client/src/main/resources/assets/nexus/backgrounds` (один источник для мода и лаунчера).
- **Автообновление** лаунчера и NEXUS Client (подробнее ниже).

## Автообновление

### Как это выглядит для игрока
- При запуске (и затем раз в 6 часов) лаунчер читает файл `nexus-update.json` из последнего релиза.
- Если есть новая версия, сверху появляется баннер «Доступно обновление»: что обновится, кнопки «Что нового», «Обновить» и «×» (скрыть до следующего запуска). **Без нажатия «Обновить» ничего не скачивается и не меняется.**
- «Обновить»:
  1. Скачивается zip-пакет NEXUS Client (хранится в `%APPDATA%\.nexus-launcher\nexus-client\`) и сразу ставится во все сборки, где NEXUS установлен. Отключённый NEXUS остаётся отключённым. Сборки, которые сейчас запущены, обновятся автоматически при следующем запуске.
  2. Скачивается zip-пакет лаунчера (содержимое папки `app`) и распаковывается рядом как `app.new`, затем лаунчер спрашивает «Перезапустить сейчас?». После перезапуска открывается уже новая версия и показывает «NEXUS Launcher обновлён до версии X». Сборки, аккаунты и настройки не затрагиваются.
- Каждый файл проверяется по SHA-256 из `nexus-update.json`. Если файл повреждён или подменён, обновление отменяется и ничего не меняется.
- Замену выполняет отдельный маленький процесс (копия класса `UpdateHelper` во временной папке). Он ждёт закрытия лаунчера, переименовывает `app` → `app.old`, `app.new` → `app` (с повторами, пока Windows держит файлы) и запускает новую версию. Если замена не удалась, `app.old` возвращается на место и запускается старая версия.
- Если лаунчер не может обновить себя сам (папка только для чтения, запуск не из установленной копии, в релизе нет пакета для этой ОС), вместо «Обновить» будет «Скачать». Кнопка откроет страницу релиза.
- Лаунчеры **1.0.0 и 1.0.1** (старая схема с jar) новый пакет не устанавливают: они ищут в манифесте ключ `win`, которого больше нет, и показывают «Скачать» → страница релиза. Нужно один раз поставить `Nexus Launcher.exe` 1.0.2 поверх — установщик сам удалит старые `NexusLauncher.exe` и `nexus-launcher.jar`. NEXUS Client эти версии обновить могут.
- В «Настройки → Обновления»: текущие версии, «Проверять обновления при запуске», «Проверить сейчас», поле для своего адреса `nexus-update.json`.

### Как выпустить обновление (для автора)
1. **Один раз:** создайте репозиторий на GitHub и впишите его в `gradle.properties`:
   ```
   update_github_repo=ваш-ник/nexus-launcher
   ```
   Лаунчер будет брать `https://github.com/ваш-ник/nexus-launcher/releases/latest/download/nexus-update.json`.
   Для своего хостинга вместо этого укажите полный адрес в `update_url=`.
   **Важно:** адрес вшивается в лаунчер при сборке. Поэтому первая версия, которую вы раздаёте игрокам, должна быть собрана уже с ним. У тех, кому достался лаунчер без адреса, его можно вписать вручную в «Настройки → Обновления».
2. Поднимите версии: `launcher_version` в `launcher/gradle.properties` и/или `mod_version` в `client/gradle.properties`.
   NEXUS Client собирается из соседней папки `../client` автоматически (`buildClient`), его версия берётся из `client/gradle.properties`.
3. Опишите изменения в `release-notes/launcher.txt` и `release-notes/client.txt`. Это текст окна «Что нового».
4. Соберите релиз:
   ```
   ./gradlew release
   ```
   В `build/release/` окажутся `Nexus Launcher.exe`, `Nexus Launcher.zip`, `nexus-update.json` и папка `updates/` с двумя zip-пакетами. Задача проверяет, что jar-файлов в результате нет.
5. Положите файлы из `build/release/updates/` в папку `updates/` репозитория (ветка `main`) и отправьте коммит.
   Пакеты нужны только автообновлению, поэтому на странице релиза их нет: `nexus-update.json` ссылается на
   `https://raw.githubusercontent.com/<репозиторий>/main/updates/<файл>`.
6. Создайте релиз GitHub (тег вида `v1.1.0`) и загрузите в него `Nexus Launcher.exe`, `Nexus Launcher.zip` и `nexus-update.json`.
   Релиз должен быть **последним** (не Draft и не Pre-release): ссылка `releases/latest` указывает именно на него.

Без `update_github_repo` (свой хостинг) ссылки в `nexus-update.json` относительные (`updates/<файл>`): выложите `build/release` целиком.

Обновить только мод можно без новой версии лаунчера: поднимите `mod_version` клиента, оставьте `launcher_version` прежней и выпустите релиз. Тогда в баннере будет только «NEXUS Client X». Лаунчер обновляется, только если его версия в релизе выше установленной.

### Формат `nexus-update.json`
```json
{
  "schema": 1,
  "page": "https://github.com/me/nexus-launcher/releases/latest",
  "launcher": {
    "version": "1.1.0",
    "changelog": "текст для окна «Что нового»",
    "files": {
      "win-app": { "url": "https://raw.githubusercontent.com/me/nexus-launcher/main/updates/nexus-launcher-1.1.0-app.zip", "sha256": "…", "size": 1012877 }
    }
  },
  "client": {
    "version": "1.1.0",
    "changelog": "…",
    "files": {
      "1.21.11": { "url": "https://raw.githubusercontent.com/me/nexus-launcher/main/updates/nexus-client-1.1.0-mc1.21.11.zip", "sha256": "…", "size": 374821 }
    }
  }
}
```
Относительные `url` считаются от адреса самого `nexus-update.json`, можно указывать и полные адреса. Файл генерирует `./gradlew release`, вручную его писать не нужно.
Для теста можно подменить адрес переменной окружения `NEXUS_UPDATE_URL` (или `-Dnexus.update.url=…`).

## Вход через Microsoft: важно

Microsoft не даёт сторонним лаунчерам общий ключ, поэтому нужен **собственный Client ID приложения Azure**:

1. [portal.azure.com](https://portal.azure.com) → App registrations → New registration.
   Тип: *Personal Microsoft accounts only*. В разделе Authentication включить *Allow public client flows*.
2. Скопировать Application (client) ID в лаунчер: **Настройки → Microsoft**.
3. **Новое приложение Mojang по умолчанию блокирует** (ответ 403 *Invalid app registration*).
   Его нужно отправить на проверку через форму <https://aka.ms/mce-reviewappid>.
   Пока одобрения нет, вход через Microsoft не заработает, причём ни в каком стороннем лаунчере.

Пароль лаунчер не видит: вход происходит на сайте Microsoft по коду. Токены хранятся в `accounts.json` в папке данных.
Без Client ID доступны офлайн-профили.

## Папка данных

`%APPDATA%\.nexus-launcher`

Внутри, среди прочего, папка `backgrounds` — свои фото для фона окна.

Папку можно переопределить переменной окружения `NEXUS_LAUNCHER_DIR` (или `-Dnexus.launcher.dir=<путь>`).

## Командная строка

Из папки программы (консольный `java.exe`, чтобы был виден вывод):
```
runtime\bin\java.exe -cp app dev.nexus.launcher.Main --list               # список сборок
runtime\bin\java.exe -cp app dev.nexus.launcher.Main --launch "<сборка>"  # запуск без интерфейса (по id или имени)
```
`"Nexus Launcher.exe" --launch "<сборка>"` тоже работает (удобно для ярлыков), но без окна консоли.

## Сборка из исходников

Нужен JDK 21 (Temurin). `gradle-wrapper.jar` нет: `gradlew`/`gradlew.bat` скачивают Gradle и проверяют SHA-256 сами.

```
./gradlew run             # запуск из классов (для разработки, на любой ОС)
./gradlew stageWin        # папка программы                       -> build/win/stage
./gradlew portableWin     # Nexus Launcher.zip                    -> build/distributions
./gradlew installerWin    # Nexus Launcher.exe (установщик)       -> build/distributions
./gradlew appPackageWin   # пакет автообновления (zip папки app)  -> build/distributions
./gradlew release         # всё для релиза                        -> build/release
```

Задача `jar` отключена — лаунчер нигде не упаковывается в jar. NEXUS Client собирается из `../client` (`-Pclient_dir=…` — другая папка, `-PclientPackage=<zip>` — взять готовый пакет).
Runtime собирается `jlink` из jmods Windows: Temurin JDK той же версии, что и JDK, на котором идёт сборка (jlink принимает только свои jmods), скачивается с api.adoptium.net, JavaFX jmods — с gluonhq.com. Из образа удаляются два служебных jar, которые jlink кладёт всегда (`lib/jrt-fs.jar`, `lib/javafx-swt.jar`): этому runtime они не нужны.
Для `Nexus Launcher.exe` нужен MinGW-w64 (`x86_64-w64-mingw32-gcc`, в Debian/Ubuntu пакет `gcc-mingw-w64-x86-64`, в Windows — MSYS2), для установщика — NSIS 3 (`makensis`, пакет `nsis`).
Иконка и картинки установщика генерируются скриптом `packaging/windows/gen_assets.py` (нужен Pillow).

## Что не сделано или не проверено

- **1.0.4** (рамка окна) проверено на Linux: кнопки и подсказки, двойной щелчок и перетаскивание к верху (разворачивание), возврат перетаскиванием и кнопкой, изменение размера за край, перемещение и закрытие окна при открытом диалоге, отключение рамки в настройках.
- **1.0.3** проверено: фон из фото, настройки «Фон» и свои фото — на Linux; самообновление 1.0.2 → 1.0.3 в Wine (скачивание, перезапуск, фон в новой версии); галочка «Моды оптимизации» и кнопка «Оптимизация» ставят все 6 модов для Fabric 1.21.11; игра с NEXUS Client 1.0.4 и этими модами запускается и загружает мир (Linux, программный рендер). Насколько вырастет FPS, здесь не измерить: нет видеокарты. Прирост зависит от компьютера.

- **Автообновление 1.0.2** проверено в Wine: 1.0.2 → 1.0.3 (тестовый пакет с локального сервера) — скачивание и распаковка `app.new`, перезапуск, замена папки, удаление `app.old`, запуск новой версии; zip NEXUS Client скачан в кеш; установка мода в сборку как `.jar` и обновление до новой версии проверены на Linux тем же кодом.
- Автообновление меняет только папку `app`. Папка `runtime` не обновляется: если будущей версии понадобятся другие модули Java, придётся один раз поставить новый установщик.
- Нет цифровой подписи обновлений, кроме SHA-256 из `nexus-update.json`. Тот, у кого есть доступ к вашему репозиторию, может выпустить что угодно. Защищайте аккаунт GitHub двухфакторной аутентификацией.

- Лаунчер выпускается только для Windows x64. Начиная с 1.0.1 сборок для Linux и macOS нет: у тех, кто поставил их из 1.0.0, баннер обновления сообщит, что для их системы сборки нет.
- Основная проверка интерфейса и запуска игр шла на Linux тем же кодом; на настоящей Windows лаунчер не запускался.
- `Nexus Launcher.exe` и установщик не подписаны цифровой подписью, поэтому при первом запуске Windows SmartScreen может предупредить («Подробнее» → «Выполнить в любом случае»). Сертификат подписи кода платный.
- exe и установщик 1.0.2 проверены в Wine 10: тихая установка поверх 1.0.1 (старые `NexusLauncher.exe`/`nexus-launcher.jar` удалены, ярлыки ведут на новый exe), запуск, отказ удаления при запущенном лаунчере, удаление с сохранением данных, портативный архив в папке с пробелом. На настоящей Windows не проверялись.
- В панели задач у окна лаунчера стоит иконка NEXUS, но закреплять в панели задач лучше ярлык из «Пуска»: само окно принадлежит процессу `javaw.exe`.
- Со своей рамкой окна (1.0.4) не работают системные функции рамки Windows: привязка окна Win + стрелки и к половине экрана, сворачивание щелчком по значку в панели задач, системное меню Alt + Пробел. Разворачивание перетаскиванием к верхнему краю сделано вручную. Нужны эти функции — выключите «Своя рамка окна» в настройках.
- Вход через Microsoft до конца не проверен: нет одобренного Mojang приложения Azure.
  Проверено, что лаунчер доходит до серверов Microsoft и правильно показывает их ошибки.
