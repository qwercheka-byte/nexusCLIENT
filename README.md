# NEXUS Launcher

Лаунчер Minecraft: Java 21 + JavaFX, Windows / macOS / Linux, оформление в стиле NEXUS Client.

## Готовые файлы

Скачать: https://github.com/qwercheka-byte/nexusCLIENT/releases/latest

| Файл | Для чего | Нужна ли Java |
|---|---|---|
| `NexusLauncher-1.0.0-windows-x64.zip` | Windows 10/11 x64. Распаковать, запустить `NexusLauncher.bat` | нет, JRE 21 внутри (`runtime/`) |
| `nexus-launcher-1.0.0-win.jar` | Windows, `java -jar` | Java 21+ |
| `nexus-launcher-1.0.0-linux.jar` | Linux x64 | Java 21+ |
| `nexus-launcher-1.0.0-mac.jar` | macOS Intel | Java 21+ |
| `nexus-launcher-1.0.0-mac-aarch64.jar` | macOS Apple Silicon (M1+) | Java 21+ |

JavaFX содержит свои нативные библиотеки для каждой ОС, поэтому jar-файлы раздельные.
Linux-архив со встроенной JRE (`NexusLauncher-1.0.0-linux-x64.tar.gz`, около 60 МБ) в `releases/` не лежит, чтобы не раздувать рабочую папку. Он собирается командой `./gradlew portableLinux`.
Java для **самой игры** лаунчер скачивает сам (официальные сборки Mojang: Java 8 / 17 / 21 / 25 в зависимости от версии).

## Возможности

- **Любые версии Minecraft** из официального манифеста Mojang: релизы, снапшоты, old alpha/beta.
  Проверено: 1.8.9, 1.20.1, 1.21.1, 1.21.4, 1.21.11, 26.3.
- **Загрузчики:** Fabric, Quilt, Forge, NeoForge (все проверены запуском). Forge и NeoForge ставятся их официальными установщиками.
- **Сборки (инстансы):** отдельная папка игры у каждой сборки; цвет, поиск, дублирование, удаление, смена версии, переустановка.
  Свои для сборки: память, Java, аргументы JVM, разрешение, полноэкранный режим, сервер для автоподключения.
- **Моды:** вкл/выкл, удаление, добавление файлов (в том числе перетаскиванием), каталог Modrinth с поиском и сортировкой.
  Установка из Modrinth идёт вместе с обязательными зависимостями; есть проверка и установка обновлений.
  NEXUS Client встроен в лаунчер и ставится одной галочкой в Fabric-сборки 1.21.4 / 1.21.11.
- **Аккаунты:** вход через Microsoft (device code), офлайн-профили (одиночная игра и серверы с `online-mode=false`).
  Скины-головы показываются в списке аккаунтов.
- **Запуск:** проверка и докачка файлов (SHA-1, параллельные загрузки), прогресс, отмена, остановка игры.
  Консоль с фильтром, копированием и логом прошлого запуска; при сбое — диалог с переходом в консоль.
- **После запуска игры** лаунчер можно оставить, скрыть до выхода из игры или закрыть.
- **Интерфейс:** русский / английский, 5 акцентных цветов.
- **Автообновление** лаунчера и NEXUS Client (подробнее ниже).

## Автообновление

### Как это выглядит для игрока
- При запуске (и затем раз в 6 часов) лаунчер читает файл `nexus-update.json` из последнего релиза.
- Если есть новая версия, сверху появляется баннер «Доступно обновление»: что обновится, кнопки «Что нового», «Обновить» и «×» (скрыть до следующего запуска). **Без нажатия «Обновить» ничего не скачивается и не меняется.**
- «Обновить»:
  1. Скачиваются новые jar NEXUS Client (для всех версий Minecraft из релиза) и сразу заменяются во всех сборках, где NEXUS установлен. Отключённый NEXUS остаётся отключённым. Сборки, которые сейчас запущены, обновятся автоматически при следующем запуске.
  2. Скачивается новый jar лаунчера, затем лаунчер спрашивает «Перезапустить сейчас?». После перезапуска открывается уже новая версия и показывает «NEXUS Launcher обновлён до версии X». Сборки, аккаунты и настройки не затрагиваются.
- Каждый файл проверяется по SHA-256 из `nexus-update.json`. Если файл повреждён или подменён, обновление отменяется и ничего не меняется.
- Замену jar выполняет отдельный маленький процесс. Он ждёт закрытия лаунчера (на Windows открытый jar заменить нельзя), делает резервную копию `*.old`, подменяет файл и запускает новую версию. Если замена не удалась, возвращается старая версия.
- Если лаунчер не может обновить себя сам (папка только для чтения, запуск не из jar, в релизе нет файла для этой ОС), вместо «Обновить» будет «Скачать». Кнопка откроет страницу релиза.
- В «Настройки → Обновления»: текущие версии, «Проверять обновления при запуске», «Проверить сейчас», поле для своего адреса `nexus-update.json`.

### Как выпустить обновление (для автора)
1. **Один раз:** создайте репозиторий на GitHub и впишите его в `gradle.properties`:
   ```
   update_github_repo=ваш-ник/nexus-launcher
   ```
   Лаунчер будет брать `https://github.com/ваш-ник/nexus-launcher/releases/latest/download/nexus-update.json`.
   Для своего хостинга вместо этого укажите полный адрес в `update_url=`.
   **Важно:** адрес вшивается в лаунчер при сборке. Поэтому первая версия, которую вы раздаёте игрокам, должна быть собрана уже с ним. У тех, кому достался лаунчер без адреса, его можно вписать вручную в «Настройки → Обновления».
2. Поднимите версии в `gradle.properties`: `launcher_version` и/или `nexus_client_version`.
   Новые jar NEXUS Client положите в `src/main/resources/bundled/` под именами `nexus-client-<версия>+mc<версия MC>.jar`, старые удалите.
3. Опишите изменения в `release-notes/launcher.txt` и `release-notes/client.txt`. Это текст окна «Что нового».
4. Соберите релиз:
   ```
   ./gradlew release                   # jar лаунчера для всех ОС + jar NEXUS Client + nexus-update.json
   ./gradlew release -Pportable=true   # то же + portable-архивы для Windows/Linux (для новых игроков)
   ```
   Всё окажется в `build/release/`.
5. Загрузите **все файлы** из `build/release/` в один релиз GitHub (Releases → Draft a new release, тег вида `v1.1.0`) или командой:
   ```
   gh release create v1.1.0 build/release/* --title "NEXUS 1.1.0" --notes-file release-notes/launcher.txt
   ```
   Релиз должен быть **последним** (не Draft и не Pre-release): ссылка `releases/latest` указывает именно на него.

Обновить только мод можно без новой версии лаунчера: поднимите `nexus_client_version`, оставьте `launcher_version` прежней и выпустите релиз. Тогда в баннере будет только «NEXUS Client X». Лаунчер обновляется, только если его версия в релизе выше установленной.

### Формат `nexus-update.json`
```json
{
  "schema": 1,
  "page": "https://github.com/me/nexus-launcher/releases/latest",
  "launcher": {
    "version": "1.1.0",
    "changelog": "текст для окна «Что нового»",
    "files": {
      "win":         { "url": "nexus-launcher-1.1.0-win.jar",         "sha256": "…", "size": 10575766 },
      "linux":       { "url": "nexus-launcher-1.1.0-linux.jar",       "sha256": "…", "size": 9348881 },
      "mac":         { "url": "nexus-launcher-1.1.0-mac.jar",         "sha256": "…", "size": 9471374 },
      "mac-aarch64": { "url": "nexus-launcher-1.1.0-mac-aarch64.jar", "sha256": "…", "size": 9435698 }
    }
  },
  "client": {
    "version": "1.1.0",
    "changelog": "…",
    "files": {
      "1.21.11": { "url": "nexus-client-1.1.0-mc1.21.11.jar", "sha256": "…", "size": 366240 },
      "1.21.4":  { "url": "nexus-client-1.1.0-mc1.21.4.jar",  "sha256": "…", "size": 326455 }
    }
  }
}
```
Относительные `url` считаются от адреса самого `nexus-update.json`, можно указывать и полные адреса. Файл генерирует `./gradlew release`, вручную его писать не нужно.
Для теста можно подменить адрес переменной окружения `NEXUS_UPDATE_URL` (или `-Dnexus.update.url=…`).

## Вход через Microsoft: важно

Microsoft не даёт сторонним лаунчерам общий ключ, поэтому нужен **собственный Client ID приложения Azure**:

1. [portal.azure.com](https://portal.azure.com) → App registrations → New registration.
   Тип: *Personal Microsoft accounts only*. В разделе Authentication включить *Allow public client flows*.
2. Скопировать Application (client) ID в лаунчер: **Настройки → Microsoft**.
3. **Новое приложение Mojang по умолчанию блокирует** (ответ 403 *Invalid app registration*).
   Его нужно отправить на проверку через форму <https://aka.ms/mce-reviewappid>.
   Пока одобрения нет, вход через Microsoft не заработает, причём ни в каком стороннем лаунчере.

Пароль лаунчер не видит: вход происходит на сайте Microsoft по коду. Токены хранятся в `accounts.json` в папке данных.
Без Client ID доступны офлайн-профили.

## Папка данных

- Windows: `%APPDATA%\.nexus-launcher`
- macOS: `~/Library/Application Support/NexusLauncher`
- Linux: `~/.local/share/nexus-launcher`

Папку можно переопределить через `-Dnexus.launcher.dir=<путь>`.

## Командная строка

```
java -jar nexus-launcher.jar --list               # список сборок
java -jar nexus-launcher.jar --launch "<сборка>"  # запуск без интерфейса (по id или имени)
```

## Сборка из исходников

Нужен JDK 21.

```
./gradlew run                          # запуск
./gradlew fatJars                      # jar для всех ОС          -> build/libs
./gradlew portableWin portableLinux    # архивы со встроенной JRE -> build/distributions
./gradlew release                      # всё для релиза с автообновлением -> build/release
```

Для portable-архивов Temurin JRE 21 скачивается с api.adoptium.net.

## Что не сделано или не проверено

- **Автообновление** проверено на Linux целиком: 1.0.0 → 1.0.1 по локальному серверу, обновление мода в двух сборках (включённой и отключённой), самозамена jar с перезапуском, отказ при неверной контрольной сумме. На Windows и macOS замена jar не проверялась (код учитывает блокировку файла на Windows). Не проверена публикация на настоящем GitHub (в этой среде нет вашего репозитория).
- Автообновление меняет только jar лаунчера. Встроенная JRE в portable-архиве не обновляется (она на Java 21 и пока не требует замены).
- Нет цифровой подписи обновлений, кроме SHA-256 из `nexus-update.json`. Тот, у кого есть доступ к вашему репозиторию, может выпустить что угодно. Защищайте аккаунт GitHub двухфакторной аутентификацией.

- Проверено только на Linux (x64). Windows и macOS не проверялись, хотя код под них есть.
- Для macOS нет `.app` и встроенной JRE — только jar, нужна установленная Java 21. Нет подписи и нотаризации.
- Для Windows нет `.exe`/установщика: запуск через `.bat` из portable-архива.
- Вход через Microsoft до конца не проверен: нет одобренного Mojang приложения Azure.
  Проверено, что лаунчер доходит до серверов Microsoft и правильно показывает их ошибки.
- Нет импорта модпаков (.mrpack, CurseForge) и каталога CurseForge.
- Иконки модов только в формате WebP JavaFX не показывает; в таком случае видна заглушка.
- Аргументы JVM, которые Mojang предлагает для версий 26.x (`default-user-jvm`), намеренно заменяются настройками памяти и JVM из лаунчера.
